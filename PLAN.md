Owner: tech lead. Source of truth: `ultimate-rovers-handoff/` (design files win on visuals, `DESIGN_SPEC.md` wins on behaviour, data and routes).

## 3. Rendering, caching and live updates

- Every public page is server rendered. Data functions in `lib/data/` read through Payload's local API and are wrapped in Next's data cache with tags (`matches`, `match:<slug>`, `players`, `articles`, `club`, and so on).
- Pages render per request on top of that cache, so no database is needed at `next build` time (the Docker build has no DB) and filtered views (`?view=`, `?competition=`) stay cheap.
- Payload `afterChange` and `afterDelete` hooks call `revalidateTag` for the affected tags and `revalidatePath` for the affected routes. Saving a match revalidates the match page, Home and Fixtures. Hooks skip revalidation when run outside Next (seed, migrations).
- Live matches: `/api/live/[slug]` returns a small uncached JSON snapshot (status, minute, score, half-time score, scorers, events). The match page wraps scoreboard and Key moments in a client `LiveMatch` provider that polls every 30 s while the status is `live` or `half_time`, pauses when `document.hidden`, and calls `router.refresh()` when the status leaves the live states so the full-time layout and tabs appear.
- Client JavaScript only for: mobile menu, nav active state, tabs, filter auto-submit, countdown, live polling, video facade, share button, accordion, forms.

## 4. URL state

| Page         | Params                                                                                 | Implementation                                                                                                                                                                                              |
| ------------ | -------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Fixtures     | `view=fixtures\|results\|table`, `competition=league\|cup\|friendly`, `season=2026-27` | Filters are a GET form: chips are real `<button name="competition" value="cup" aria-pressed>`, so they work without JS. Season select auto-submits. Tabs are links with `role="tab"`, enhanced client side. |
| Match centre | `tab=overview\|lineups\|stats\|report\|h2h`                                            | Same tabs component. Invalid tab for the current state falls back to overview, as in the design logic.                                                                                                      |
| Squad        | `position=goalkeepers\|defenders\|midfielders\|forwards`                               | GET form chips.                                                                                                                                                                                             |
| Player       | `stats=season\|career`                                                                 | Segmented tabs.                                                                                                                                                                                             |
| News         | `category=`, `q=`, `page=`                                                             | GET form for search and chips, link pagination.                                                                                                                                                             |
| Contact      | `topic=general\|tickets\|partnerships\|media\|academy`                                 | Preselects the topic select.                                                                                                                                                                                |

All params are parsed with zod in `lib/search-params.ts`; anything invalid falls back to the default.

## 5. Content model (Payload)

## 9. Risks

- Next 16 plus Payload 3: supported from Payload 3.6x, pinned to matching versions.
- Build without a database: handled by request-time rendering over the data cache (section 3).
- Placeholder seed data: every seeded string keeps the bracket convention so nothing can be mistaken for a real club fact. Seeded numbers only attach to bracketed placeholder teams and players.
